Sesión 3: Cómo Construir un Chatbot Corporativo & Agentes Autónomos

🎯 Objetivo pedagógico: Llevar a Anabela desde los chatbots informativos (IA Pasiva / RAG) hacia los sistemas agénticos capaces de ejecutar acciones en sistemas empresariales (IA Activa): ciclo de razonamiento ReAct, arquitectura multi-agente Orchestrator-Workers, Tool Calling JSON, frenos Human-in-the-Loop y validación estructurada con Pydantic.

⚡ MACHETE GENERAL DE 60 SEGUNDOS (LEÉ ESTOS 4 PUNTOS 1 MINUTO ANTES DE EMPEZAR LA LLAMADA)
1. El Gran Cambio (Slides 1 a 3)

En la Sesión 2 vimos IA Pasiva (RAG): un bibliotecario que lee manuales y responde, pero no toca sistemas. Hoy vemos IA Activa (Agentes): un asistente con manos propias que usa el bucle ReAct (Pensar → Actuar → Observar) para consultar Jira, validar datos y ejecutar tareas.

2. Trabajo en Equipo y Herramientas (Slides 4 a 6)

Para que el agente no se confunda, dividimos el trabajo con Orchestrator-Workers (un coordinador y varios especialistas). El agente nunca entra directo a la base de datos: pide usar herramientas en formato JSON (Tool Calling / MCP) y aceleramos su velocidad con KV Cache.

3. Control Humano y Caso Real (Slides 7 a 9)

Las decisiones caras o irreversibles llevan un freno obligatorio (Human-in-the-Loop / HITL). Además, para que la IA no rompa Jira ni bases de datos con texto suelto, filtramos su salida con un molde estricto de datos (Pydantic).

4. Blindaje de Costos y Seguridad (Slides 10 a 15)

Evitamos facturas gigantes por bucles de error poniendo un tope de intentos (Max Iterations = 5), diseñamos un Plan B (Fallback) si se cae una API, protegemos la base de datos con un API Gateway y practicamos cómo defender esta arquitectura ante un CTO.

Loops de Razonamiento: La Arquitectura ReAct (Reason + Act)

ReAct Loop · Thought · Action · Observation ⏱️ 4 Min
⚡ MACHETE EXPRESS DE 5 SEGUNDOS (SI NO REPASASTE, MIRÁ SOLO ESTAS 3 CAJAS MIENTRAS COMPARTÍS PANTALLA)
🎯 1. IDEA CENTRAL EN 1 FRASE

Un agente no responde por impulso: sigue un ciclo de 3 pasos llamado ReAct (1. Pensar, 2. Actuar con una herramienta, 3. Observar el dato real).

👆 2. QUÉ TOCAR EN LA SLIDE

🎙️ GUION PASO A PASO EN 3 BLOQUES CORTOS (SI QUERÉS LEERLO TEXTUAL)
Hacé clic conmigo en cada uno de los tres círculos de este diagrama porque así piensa un agente por dentro. El patrón se llama ReAct (Reason + Act) y funciona como un bucle de tres pasos: 1) Thought (Pensamiento): El agente recibe tu pedido y razona en voz baja: 'El usuario quiere saber el estado de entrega de los módulos del sprint. Para no inventar, necesito consultar la API de Jira/TMS'. 2) Action (Acción): El agente elige la herramienta adecuada y prepara el pedido formal para la API (por ejemplo, get_sprint_module_status(project_id='99')). 3) Observation (Observación): El servidor ejecuta esa consulta en vivo y le devuelve el dato real al agente ('8 de 10 módulos listos, 2 bloqueados en QA'). El agente observa ese resultado y decide si ya puede responderte o si tiene que dar otra vuelta al bucle.

🔹 ReAct (Reason + Act)

Técnica que obliga a la IA a escribir primero su razonamiento ('Thought'), elegir una herramienta ('Action') y leer el resultado ('Observation') antes de hablar.

🔹 Traza de Pensamiento

El borrador interno donde el agente anota qué dato le falta y qué API necesita consultar.

Tool Calling · Function Calling · JSON Schema · Seguridad Backend ⏱️ 4 Min

El modelo de IA no se mete por su cuenta a la base de datos: genera un pedido estructurado en JSON (ej. call_mcp_tool) y Antigravity ejecuta la consulta oficial y segura.

🎙️ GUION PASO A PASO EN 3 BLOQUES CORTOS (SI QUERÉS LEERLO TEXTUAL)
Esta diapositiva responde una duda técnica clave: '¿Le damos permiso a ChatGPT para que entre directo a nuestra base de datos?'. ¡Jamás! El LLM nunca toca tu base de datos; lo hace a través de Tool Calling (Llamada a Herramientas). Vamos a probarlo en vivo haciendo clic en el botón de la consola derecha: Fijate que el usuario pregunta por la capacidad del Proyecto #4. En el primer clic, el LLM piensa qué función necesita y escupe un texto estructurado en formato JSON: {"function": "get_project_capacity", "arguments": {"project_id": 4}}. El LLM solo pide apretar ese botón. En el segundo clic, es nuestro propio servidor Backend (seguro y determinista) el que lee ese JSON, consulta la base de datos real y le devuelve que se usaron 485.5 horas de 500 max. Y recién ahí el LLM redacta la respuesta amigable para el usuario.
💡 Explicación en Palabras Simples (Cómo explicárselo claro a Anabela)
🔹 Tool Calling (Llamada a Herramientas)

La capacidad de la IA de pedir que se ejecute una función del sistema (igual a lo que hace Antigravity cuando usa el servidor MCP de AWS).

🔹 Probabilístico vs. Determinista
