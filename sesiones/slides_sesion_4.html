AI Economics: La Variable GPU

Por qué desarrollar software de IA no es gratis y cómo se estructura la facturación de tokens.

Costo Unitario de Inferencia

A diferencia del código clásico ejecutado localmente, cada llamada a la API de OpenAI o Anthropic factura por tokens (sub-palabras).

  • Input Tokens (Prompt): Las instrucciones de sistema, datos recuperados por RAG e inputs del usuario.
  • Output Tokens (Response): Las palabras generadas por el modelo. Suelen costar entre 3 y 4 veces más debido a la memoria de autoregresión de la GPU.

REGLA MÉTRICA PM

1k Tokens ≈ 750 Palabras

En español, requiere un 20% a 30% más de tokens por término debido a raíces gramaticales complejas.

Perspectiva PM: Un prompt mal optimizado o con datos irrelevantes inyectados duplica directamente el costo operativo unitario (COGS) de tu aplicación de IA.

Prompt Caching: El Súper Ahorro

Cómo evitar calcular tokens repetitivos turno tras turno, bajando costos hasta en un 90%.

¿Cómo funciona el Caching?

El API de inferencia guarda el estado matemático (KV Cache) de los tokens fijos del System Prompt o de manuales extensos inyectados por RAG en la memoria RAM de la GPU.

En turnos de chat sucesivos, el modelo lee la caché de inmediato sin volver a procesar los tokens fijos, cobrándote solo una fracción mínima de la tarifa normal.

Aceleración: Además de ahorrar dinero, baja radicalmente el Time to First Token (TTFT), ya que el modelo empieza a escupir palabras casi al instante.

RAG vs. Fine-Tuning: Costos de Negocio

El balance financiero y de mantenimiento que tenés que justificar al proponer soluciones.

Dimensión RAG (Vector Database) Fine-Tuning (Ajuste Fino)
Costo de Configuración Bajo (Conector de datos, chunker y carga a base vectorial). Alto (Requiere preparar miles de pares pregunta-respuesta).
Actualización de Datos Instantáneo y sin costo (Añadir o remover un PDF). Muy costoso (Requiere volver a entrenar el dataset completo).
Alucinaciones Bajo (Ancla su respuesta a fragmentos reales citables). Medio-Alto (No previene que invente datos lógicos ausentes).
Foco de Negocio Enseñar QUÉ decir (Datos actualizados). Enseñar CÓMO hablar (Tono y formato).
Regla de Decisión PM: Casi siempre empezá con RAG. Solo pasá a Fine-Tuning si necesitás obligar al modelo a responder con un formato JSON milimétrico que no tolera fallas sintácticas de API.

Seguridad Corporativa: Fuga de Datos

Cómo blindar los datos comerciales sensibles de la empresa para evitar filtraciones indeseadas.

Riesgo de Data Leakage

Si los operarios o el propio agente inyectan información sensible (tarifas confidenciales, contratos de clientes, datos personales PII) en llamadas a APIs de LLM externas.

Los proveedores estándar pueden almacenar y usar esa información para re-entrenar sus modelos públicos, exponiendo tus datos comerciales a competidores.

Mitigaciones Corporativas

  • Enterprise API Contracts: Acuerdos legales con políticas de exclusión de entrenamiento (Zero Data Retention).
  • API Gateway Proxy: Filtros de seguridad locales que ofuscan o limpian PII (Datos Personales) o PI comercial antes de llamar al LLM externo.
  • Bases de Datos Vectoriales Propias: Servidas en tu nube elástica privada y protegidas con controles de acceso por inquilino.

Suite de Evaluaciones (AI Evals)

El desafío de testear software no-determinista y cómo se audita científicamente la precisión semántica.

Del Testing Manual a Evals

Chatear cinco minutos con el bot no sirve para validar calidad en producción. Al ser probabilístico, un prompt que funcionó hoy puede dar una alucinación mañana.

Se requiere una suite de Evals automatizadas que compare la salida del agente contra rúbricas semánticas y retorne scores de exactitud.

Métricas Semánticas de Calidad

  • Fidelidad (Faithfulness): ¿La respuesta se basa estrictamente en la documentación oficial recuperada (cero alucinación)?
  • Relevancia de Contexto: ¿La base de datos vectorial recuperó los fragmentos exactos del módulo o glosario consultado?
  • Relevancia de Respuesta: ¿Resuelve directamente la consulta del usuario o analista?

Preparación de Entrevistas de PM IT/IA

Cómo plantarse frente a un Hiring Manager técnico y defender tu posicionamiento estratégico.

El Perfil del PM IA

Los reclutadores de tecnología no buscan a un programador de modelos. Buscan a un PM que entienda la gobernanza técnica y la viabilidad financiera del producto.

Debés demostrar que sabés hablar tanto el idioma técnico de los desarrolladores (APIs, latencias, evals) como el de los gerentes de finanzas (COGS, ROI, presupuestos).

Tres Pilares de Defensa del PM

  • Gestión Financiera: Argumentar mitigación de facturas descontroladas de tokens (prompt caching, limits).
  • Gobernanza de Seguridad: Evitar fuga de datos del negocio (PII) mediante proxies y gateways de APIs.
  • Aseguramiento de Calidad: Explicar suites de pruebas automatizadas (Evals) contra alucinaciones.
