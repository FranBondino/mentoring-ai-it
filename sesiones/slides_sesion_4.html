FinOps 1: Model Routing (enrutamiento de modelos)

Un filtro previo deriva ~80% de las consultas simples a un modelo económico y reserva el grande para casos complejos.

Dos carriles según complejidad

Carril rápido (70% - 85% del tráfico) · Modelos chicos Gemini Flash, Claude Haiku, GPT-4o-mini, AWS Nova Micro. ~$0.15 / 1M tokens · ~0.3s · Clasificación, extracción y dudas directas.
Carril complejo (15% - 30% del tráfico) · Modelos grandes Claude Sonnet/Opus, GPT-4o, Gemini Pro. $3 a $15 / 1M tokens · Contratos ambiguos, transcreación y varios pasos.

FinOps 2: Batch API (-50%) y costos ocultos (TCO)

Pagá la mitad en tareas sin urgencia y sumá los gastos fijos que quedan fuera del precio por token.

Tiempo real vs. Batch API (-50%)

Síncrono (tarifa 100%) Chat en vivo o asistente en pantalla donde la persona espera respuesta en menos de 2 segundos.
Batch API / Asíncrono (tarifa 50%) Pre-traducción nocturna de releases, control de glosarios o análisis histórico en 1-12 hs (AWS Bedrock Batch / OpenAI Batch).

4 costos ocultos del TCO

1. Vueltas del agente: Cada paso ReAct reenvía el contexto acumulado varias veces.
2. Infraestructura fija: Alojamiento de Vector DB + Langfuse (~$70 a $250 USD/mes).
3. Idioma (ES/PT vs. EN): Español y portugués consumen ~20-30% más tokens.
4. Evals y revisión humana: Auditorías automáticas + tiempo de validación del equipo.

Build vs. Buy vs. Configure (y cómo evitar Vendor Lock-in)

Evaluá si alcanza con una licencia lista o conectar plataformas antes de pedir desarrollo propio.

BUY · SAAS

Comprar algo listo

Plazo: días · Sin equipo dev.
Resúmenes de llamadas, DeepL Pro o soporte estándar que no diferencia al negocio.

CONFIGURE

Conectar plataformas

Plazo: 1-3 semanas · Bajo mantenimiento.
Pilotos internos conectando Jira, Slack o repositorios (Bedrock KB, n8n, MCP).

BUILD · GATEWAY

Desarrollo a medida

Plazo: meses · Devs dedicados.
Solo si es clave para el producto. Usá un Model Gateway (Bedrock / LiteLLM) para cambiar de modelo.

Casos prácticos: ¿qué elegirías?
Conviene BUY (SaaS) · ~3 días — Resumir reuniones no diferencia a la empresa. Mantener un transcriptor propio desperdicia tiempo de ingeniería frente a una licencia corporativa.

AI Evals en la práctica: Tríada RAG, Agentes y Model Drift

Qué área del sistema corregir según la métrica que cae y qué suma evaluar agentes.

Qué métrica baja → qué tocás en el Sprint

1. Fidelidad (Faithfulness) baja — Inventó datos fuera del manual. Backlog: System Prompt, Temperatura 0.0 o Guardrail de cita obligatoria.
2. Precisión de Contexto baja — El buscador trajo fragmentos irrelevantes. Backlog: Chunking, Metadatos o Top-K en la Vector DB.
3. Relevancia baja — Contestó sin resolver la pregunta puntual. Backlog: Formato, extensión y estructura de respuesta.

Más allá de RAG: Agentes y Model Drift

Trajectory Evaluation (Agentes) Medir si eligió la herramienta correcta (Tool Accuracy), armó el JSON y evitó pasos extra.
Model Drift y criterio humano (SME) El proveedor puede variar calidad sin aviso. Calibrar LLM-as-a-Judge requiere criterio de idioma y dominio (QA/Traducción).

Cómo encarar entrevistas técnicas y defender tu perfil

No esperan código: evalúan cómo investigás con datos, qué trade-off aceptás y cómo medís impacto.

Estructura en 3 pasos

1. Diagnóstico con datos Cruzar trazas en Langfuse y hablar con usuarios antes de pedir cambios de modelo o prompt.
2. Propuesta y trade-off Proponer un Spike de 1 semana o Routing por categoría, aclarando qué queda afuera hoy.
3. Métrica de corte Definir de entrada cómo medís éxito: adopción semanal, nota en Evals o costo por consulta.
